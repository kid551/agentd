按 DeepSeek《Super-agent 设计探索》的双层架构，在本仓库搭一套只服务于你一个人的 Router / Worker 系统：你只跟一个 Router 会话说话，它把活派给各项目目录下的 Worker 会话；Worker 会话在 VSCode 的 Claude Code 插件里原生可见；所有需要你拍板的问题汇总回 Router，并且随时清楚「我现在在批哪一个」。

三个运行单元，各自职责一句话：

  • agentd（守护进程）：事实源。存工单与事件、派 Worker、收 Worker 汇报、扫项目。无 LLM、无 UI。Router 不在线它照收。
  • router-mod：Router 会话的「外挂」。把 agentd 的事件批量注入 Router，画 Pane 与 band，给 Router 提供 agentd_* 工具，禁掉 Router 的执行类工具，把你的回复直通给 Worker。
  • agentd-mcp：Worker 会话里的 MCP server，三个工具：汇报、提问（阻塞等答复）、完工。只是 agentd HTTP 的薄壳。
决策 A · Worker 用 claude --bg 而不是 agentd 自己 spawn 子进程
理由：--bg 是 Claude Code 原生的后台会话机制，自带守护、claude agents 列表、attach、崩溃后 respawn；Worker 的生命不绑在 Router 或 VSCode 上，你关掉 VSCode 它继续干。transcript 写在目标项目的 ~/.claude/projects/<项目>/<session-id>.jsonl，VSCode 的会话列表原生能看到。代价：Worker 的输出流不经过 agentd，agentd 对 Worker 的感知依赖它主动调 agentd_report 以及轮询 claude agents --json 的 busy/idle/exited 状态。
决策 B · 问题答复走「阻塞式工具」，追加指令走原生会话消息
Worker 问问题时调 agentd_ask，这个 MCP 工具会长轮询 agentd 直到你的答复到达才返回，Worker 这一轮一直挂着，跟原生 AskUserQuestion 的体验完全一致，并且在 Worker 的 VSCode tab 里能看到它正在等什么。答复的投递因此不依赖 Router 在线，未来 IM / CLI 也能答。
你要给一个空闲 Worker 追加新指令时（没有待答问题），Router mod 用引擎原生的 $.session.send({ to: "agentd-w-12" })，即 SendMessage 的底层。

3. 数据模型 最可能要调

只有 4 张表，概念直接沿用 PDF / 参考仓库的词：Ticket（工单）、Event（事件）、Question（待人工决定，参考仓库叫 Attention）、Project（注册表）。v1 不做 Thread / Source / Mandate 这些实体，只留字段位。

Ticket · 工单

id          INTEGER PK          -- 短号，#12 就是它，所有界面只用这个
title       TEXT                -- Router 起的一句话标题（≤ 30 字）
project_id  TEXT → projects.id
prompt      TEXT                -- 派给 Worker 的完整任务描述
state       TEXT                -- 见下表
worker_session_id  TEXT         -- 预生成的 UUID，用于 deeplink 和 jsonl 定位
worker_name        TEXT         -- agentd-w-<id>，$.session.send 的地址
worker_bg_id       TEXT         -- claude --bg 打印的短 id，用于 stop / logs / respawn
worktree    INTEGER             -- 0/1
model       TEXT                -- 默认 opus
source      TEXT                -- v1 恒为 'router'；v2: github / feishu
last_report TEXT                -- 最近一次 Worker 摘要（Inline 用，≤ 300 字）
created_at / updated_at / ended_at
state含义谁能把它变成这样Pane 分组
queued同项目有别的 Worker 在跑，排队agentd进行中
workingWorker 在干agentd（spawn 成功 / 收到 progress 汇报）进行中
asking有未答的 QuestionWorker 调 agentd_ask待我处理
readyWorker 说可以验收了Worker 调 agentd_done(outcome=ready)待我处理
blocked / failedWorker 卡住 / 进程异常退出Worker 汇报，或 agentd 轮询发现进程没了且无 done待我处理
done你验收通过或 Worker 说无事可做你（Router 工具 agentd_close）或 Worker outcome=dropped已结束
stopped你叫停你已结束

规则：ready 之后你说「继续改 X」，工单回到 working（同一个 Worker 会话，$.session.send 唤醒）；不会新开工单。

Event · 事件（append-only，链式召回的材料）

id, ticket_id, ts, kind, actor, body(JSON)
kind ∈ dispatched | spawned | progress | ask | answer | message_to_worker | ready | blocked | failed | done | stopped | worker_exited
actor ∈ you | router | worker | agentd

Question · 待人工决定

id, ticket_id, asked_at, question TEXT, options JSON(可空), answered_at, answer TEXT
-- 一个工单同一时刻最多一个未答 Question（Worker 阻塞在 agentd_ask 上，天然保证）

Project · 项目注册表

id (目录名，重名时加父目录), path, root, default_branch, last_seen_at
-- 启动时及每 10 分钟扫一次 config.roots，maxdepth 3 找 .git

配置 ~/.agentd/config.json

{
  "roots": ["~/code"],
  "port": 7707,
  "worker": { "model": "opus", "permissionMode": "auto", "maxConcurrent": 4 },
  "router": { "inlineChars": 300, "batchIdleMs": 1500 }
}

数据库在 ~/.agentd/agentd.db，日志在 ~/.agentd/logs/。仓库本身不存运行状态。

4. 接口 最可能要调

4.1 Worker 侧 MCP 工具（agentd-mcp，Worker 唯一的汇报通道）

工具参数行为
agentd_report{ summary }记一条 progress 事件，刷新 last_report。非阻塞。Worker 系统提示要求它在每个阶段性节点调一次（≤ 300 字）。
agentd_ask{ question, options?: string[] }建 Question，工单→asking，长轮询直到有答复才返回（期间每 20s 发 MCP progress 通知保活）。返回 { answer }。
agentd_done{ outcome: ready | blocked | failed | dropped, summary }工单进入对应状态。ready 的 summary 要写清「改了什么、怎么验证、你需要看哪里」。

工具通过环境变量 AGENTD_TICKET、AGENTD_URL 知道自己是谁；Worker 不可能冒充别的工单。

4.2 Router 侧工具（router-mod 用 $.tool.register 注册，Router 模型调用）

工具参数行为
agentd_dispatch{ project, title, prompt, worktree?, model? }解析项目名（唯一匹配才通过，否则返回候选让 Router 问你），POST /tickets，返回 #id。
agentd_status{}一屏总览：待处理 / 进行中 / 24h 内结束，每行一句。
agentd_read{ ticket, what: summary | events | transcript, limit? }链式召回的「下一跳」：summary 给工单全文 + 最近汇报；events 给事件流；transcript 给 Worker jsonl 的最后 N 条（从 ~/.claude/projects 直接读）。
agentd_answer{ ticket, answer }回答该工单的待答 Question（agentd 收到后 agentd_ask 的长轮询返回）。
agentd_message{ ticket, text }给无待答问题的 Worker 追加指令：记事件 + $.session.send({ to: worker_name, text })。
agentd_close / agentd_stop{ ticket }验收关闭 / 叫停（claude stop <bg_id>）。

4.3 agentd HTTP API（127.0.0.1 only，无鉴权；给 mod 和 mcp 用）

GET  /status
GET  /projects
GET  /tickets?state=open|needs_me|all
GET  /tickets/:id            GET /tickets/:id/events     GET /tickets/:id/transcript?tail=N
POST /tickets                { project, title, prompt, worktree?, model? }
POST /tickets/:id/report     { summary }                           ← mcp
POST /tickets/:id/ask        { question, options? }  → 长轮询        ← mcp
POST /tickets/:id/done       { outcome, summary }                   ← mcp
POST /tickets/:id/answer     { answer }
POST /tickets/:id/message    { text }        -- 只记事件；实际投递由 mod 的 $.session.send 完成
POST /tickets/:id/stop  /close
GET  /events?since=<cursor>&wait=25   -- 长轮询，mod 的事件源

4.4 派工命令（agentd 内部，供核对）

cd <project.path> && claude --bg \
  -n agentd-w-<id> --session-id <uuid> --model opus --permission-mode auto \
  --mcp-config ~/.agentd/mcp/<id>.json \          # 含 AGENTD_TICKET / AGENTD_URL 的 agentd-mcp 配置
  --append-system-prompt-file <packages/agentd/prompts/worker.md> \
  [--worktree agentd-<id>] \
  "<prompt>"

5. 用户可见的交互 最可能要调

5.1 一天的样子

  1. 你在 agentd 工作区打开 Claude Code，会话加载 router-mod。右侧 Pane「工单」出现，空的。
  2. 你说：「在 acme-flutter 里把列表滚动掉帧修了，先别动数据层。」Router 调 agentd_dispatch，回你一句「#12 acme-flutter · 修复列表滚动掉帧 · 已派」。Pane 多一行。
  3. 你接着派 #13、#14。三个 Worker 并行干。Router 安静。
  4. #12 的 Worker 调 agentd_ask：「掉帧根因是 ListView 没加 itemExtent，加上会固定行高；行高固定可接受吗？」
    mod 收到事件，等 Router 这一轮结束后注入一条：
    【#12 · acme-flutter · 修复列表滚动掉帧】问：… 选项：A 固定行高 / B 用 prototypeItem
    Router 转述给你（≤ 100 词），band 自动变成「正在批 #12 · acme-flutter · 修复列表滚动掉帧 · 直通 Worker」。
  5. 你直接打「A，但 prototypeItem 也写个 TODO」。因为 #12 有待答问题且被聚焦，mod 直通：你的话不经 Router 模型，直接 POST answer，Worker 的 agentd_ask 返回继续干。Router 的 transcript 里只留一行「→ #12 已答」。
  6. #13 和 #14 几乎同时 done(ready)。mod 合并成一条注入，Router 说「#13、#14 已就绪待验收」，Pane 的「待我处理」里两行，各有 [在 VSCode 打开] 按钮。你点开 #13 的 Worker tab 看 diff，满意，回 Router 说「13 收了」→ agentd_close。
  7. 晚上关 VSCode，#14 还有个 Worker 在跑测试。第二天打开 Router，mod 的 session.start 钩子注入 agentd_status 快照，Router 开口第一句就是总览。

5.2 band（输入框上方常显一行）

聚焦有待答问题：   ▶ 正在批 #12 · acme-flutter · 修复列表滚动掉帧 · 你的话直通 Worker   (/r 改为对 Router 说)
聚焦但无待答问题： ▶ 关注 #12 · acme-flutter · 修复列表滚动掉帧 · 你的话经 Router 转给 Worker
无聚焦：           ○ 未聚焦工单 · 待处理 2 · 进行中 3     (/next 跳到下一个待处理)
决策 C · 直通（Fast Path）的边界
聚焦工单有未答 Question 时，你的输入默认直通 Worker，不消耗 Router 一轮，这是 PDF「已订阅走直通」在个人场景的对应。例外：以 / 开头的命令；以 /r 开头的话发给 Router。无未答 Question 时一律先到 Router，由它决定是追加指令（agentd_message）还是新派工单。如果你觉得直通太「硬」，改成「全部经 Router」只是关一个开关。

5.3 Pane「工单」

待我处理 (2)
  #12  acme-flutter   修复列表滚动掉帧          问 · 3 分钟前    [聚焦] [打开]
  #13  billboard          接入新榜单 API             就绪 · 刚刚      [聚焦] [打开] [收]
进行中 (1)
  #14  acme-compute   补 ETL 单测                干 · 12 分钟      [打开] [停]
已结束 · 今天 (3)  ▸

按钮行为：[聚焦] 改 band 焦点；[打开] open vscode://anthropic.claude-code/open?session=<worker_session_id>；[收] / [停] 调对应工具。所有文字中文，不出现 UUID。

5.4 slash 命令

/next聚焦到最早的待处理工单，并把它的问题/就绪摘要再贴一次
/focus 12 · /unfocus手动切换焦点
/tickets在聊天里打印一份与 Pane 相同的总览（没有 Pane 的 surface 用）
/r <话>直通状态下强制对 Router 说

5.5 Router 的说话风格（prompt.compose 注入）

  • 只做三件事：派工、转述 Worker 的问题与结果、把你的回答路由出去。不读代码、不改文件、不跑命令。
  • 每次回复 ≤ 100 词，永远以 #工单号 开头指明在说哪个工单；一次只问一个问题。
  • 派工前若项目名多义或任务范围不明，问一次；不自作主张扩大范围。
  • 要细节先调 agentd_read，不要凭记忆。

6. Router 的上下文管理：PDF 机制 → 落地

PDF落地依赖的引擎能力（已在类型文件确认）
Router 不执行、只路由tool.call 钩子在 Router 会话拒绝 Edit / Write / Bash / NotebookEdit / Agent，返回提示「派给 Worker」。Read / Grep / agentd_* 放行。on('tool.call', …) → { deny }
Batchingmod 长轮询 /events；事件先进内存队列；turn.start / turn.complete 跟踪 Router 是否在推理；空闲 1.5s 后把队列合并成一条注入。推理中到达的事件等这轮结束。$.prompt.submit({ text })、turn.start、turn.complete
Inline & Spill注入文本每工单只带：#id、项目、标题、事件类型、≤ 300 字摘要。全文留库。—（agentd 侧截断）
链式召回agentd_read(ticket, what) 三跳：summary → events → transcript。每跳结果内联下一跳的 ID。$.tool.register、$.fs.read（读 jsonl）
Router 的长程记忆事实源在 SQLite，不在 transcript。session.start 注入状态快照；session.compact 钩子在 compact 指令里追加「保留工单表与焦点」。session.start、session.compact
订阅直通决策 C：聚焦工单有待答问题时，prompt.submit 钩子截获你的输入直接 POST answer，返回 { consumed } 不进模型。on('prompt.submit', …) 可消费
Worker 不直接对人说话Worker 的系统提示：对外只通过三个 agentd 工具；不用 AskUserQuestion（Router 会话收不到）。worker.md
异步 ReActWorker 侧沿用 Claude Code 自身的后台任务机制，不另做。—

7. 第 0 步：必须先验证的 5 个点

这些是方案成立的前提，每个都是半小时内能做完的实验，任何一个不成立都有写好的退路。实施从这里开始，验证结果记进 implementation-notes.md。

S1 · claude --bg 的参数组合与可见性
在一个真实项目目录跑 claude --bg -n agentd-w-0 --session-id <uuid> --model sonnet --permission-mode auto --mcp-config x.json --append-system-prompt "…" "列出当前目录三个文件后结束"。验证：① 进程起来且 claude agents --json 能看到名字与状态；② jsonl 出现在该项目的 projects 目录；③ 打开该项目的 VSCode 窗口，会话列表里出现；④ open "vscode://anthropic.claude-code/open?session=<uuid>" 能定位到它（在 agentd 窗口和项目窗口各试一次）。
退路：④ 跨工作区不行 → Pane 的 [打开] 改为先 open -a "Visual Studio Code" <项目路径> 再 deeplink，或 Pane 内直接展示 transcript 尾部。
S2 · 空闲的 bg Worker 能被会话间消息唤醒
S1 的 Worker 结束一轮后空闲；从另一个会话 SendMessage 给 agentd-w-0「再列两个文件」。验证它醒来干活。
退路：不行 → agentd_message 改为 claude stop 后 claude --bg --resume <uuid> "<text>"（help 里写明支持 --resume 的后台续跑）。
S3 · 阻塞式 MCP 工具能挂 > 10 分钟
agentd-mcp 的 agentd_ask 原型：每 20s 发一次 progress 通知，15 分钟后返回。验证 Claude Code 不超时杀掉。
退路：超时 → agentd_ask 改为非阻塞「已记录，结束本轮」，答复改由 S2 的通道投递；若 S2 也不行，用退路 resume。
S4 · router-mod 能在 VSCode 的会话里加载并画出 Pane / band
最小 mod：session.start 时 $.ui.open 一个 Pane 写「hello」，AbovePrompt 画一行。加载方式二选一验证：agentd 仓库 .vscode/settings.json 的 claudeCode.environmentVariables 设 CLAUDE_CODE_PLUGIN_DIRS；或 .claude/settings.json 的 enabledPlugins 指向本地 marketplace。
退路：VSCode surface 不画 Pane → band + /tickets 命令兜底，Pane 只在终端用。
S5 · $.prompt.submit 从时钟钩子注入能成为一轮用户消息，且 prompt.submit 钩子能消费掉你的输入
mod 用 $.clock.after(5000) 注入一句话，看 Router 是否响应；再写一个 prompt.submit 钩子对以 ! 开头的输入返回 consumed，看模型是否确实没收到。
退路：注入不行 → 退化为 band 提示「有 2 条新事件，/next 查看」，由你触发。

选择理由
Node 24 + TypeScript，pnpm workspace你的 CLAUDE.md 要求；mod 本身只能是 TS/TSX
node:sqlite（Node 22.5+ 内置）零原生依赖，launchd 下无需编译；单机单写者，不需要更重的库
HTTP 用 node:http，不引框架十几个路由，框架是负资产
MCP 用官方 @modelcontextprotocol/sdk唯一的外部运行时依赖，保活用它的 progress 通知
脚本名避开 pnpm 保留字serve / check / fmt / lint / install:launchd，见 pnpm-scripts-naming
不用 Python全栈 TS，省掉一套解释器约束

10. 明确不做的事 / 风险

  • 不改 VSCode 插件、不 patch Claude Code。全部能力来自公开的 mod API、CLI 参数与 deeplink。版本升级若破坏某条，退路见第 7 节。
  • v1 不接任何外部 Source（GitHub / 飞书 / 文件监听 / 定时）。表结构留 source 字段，v2 加一个 packages/source-github 往 /tickets POST 即可，Router / Worker 侧零改动。
  • 不做 Watchdog Session。v1 的「看门狗」只是 agentd 轮询进程存活 + 失败状态进「待我处理」。模型判断 Worker 是否偏航，留 v2。
  • 不做 Router 水平切分、不做 Thread / Mandate 实体。一个人的事件量到不了那个规模。
  • Worker 不开分支、不 push，除非工单 prompt 明说。这是 worker.md 里的硬约束，与你的全局规则一致。
  • 风险：Router 在 VSCode 里，VSCode 关了 Router 就不在。Worker 和 agentd 不受影响，事件在库里攒着；这是你选的形态，可接受。若日后想要 Router 持久在线，把 Router 本身也用 claude --bg 起、VSCode 用 attach 连上去，mod 不用改。
  • 风险：同一项目串行。两个任务都要改 acme-flutter 时第二个排队。想并行就对第二个说「用 worktree」。
  • 风险：Worker 不守规矩（直接 AskUserQuestion 而不是 agentd_ask）。agentd 轮询到 Worker 长时间 idle 且无 ask/done 时，标为 blocked 并提示「Worker 可能在 tab 里等你」，Pane 的 [打开] 能救。

11. 分发给其他人（macOS / Windows）

三个运行单元里只有 mod 是「源码即产物」。整个仓库作为一个 Claude Code plugin 分发，plugin 内含 mod 源码 + 两个 build 好的单文件；对方只需要 Claude Code 和 Node 24，不需要 clone、pnpm。

单元对方机器需要build
router-modClaude Code（引擎自己编译 register.tsx；模块内不得 import npm 包）无
agentd 守护进程Node 24tsdown 打成 dist/agentd.mjs 单文件
agentd-mcpNode 24tsdown 打成 dist/agentd-mcp.mjs 单文件
  • 安装入口：仓库根 .claude-plugin/marketplace.json；对方 /plugin install agentd --marketplace TerenceXie/agentd。试用可 claude --plugin-url <Release zip>。
  • 产物位置：dist/ 不提交，pnpm build 后打 tag 发 GitHub Release zip。
  • 守护进程自举（第 10 步）：mod 起 node <plugin>/dist/agentd.mjs，Windows 无需 launchd / 任务计划。
  • 个人配置（roots 等）走 plugin userConfig，首次加载问一次。
  • Windows 差异：deeplink 用 cmd /c start 代替 open，按 process.platform 分支；claude --bg 与 ~/.claude/projects 路径转义在 Windows 上未验证，标为「仅 macOS 验证」。
