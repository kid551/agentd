agentd 本地 Super-agent：一个入口，批阅多个 Claude Code Worker

你只跟一个 Claude Code 会话说话，它叫 Router。Router 把活派给若干 Worker：每个 Worker 是在某个项目目录里运行的独立后台 Claude Code 会话，在 VSCode 的会话列表里原生可见。Worker 的提问、交付、受阻都汇总回 Router；输入框上方常显一行，告诉你此刻在批哪一张奏折。

思路来自 DeepSeek《Super-agent 设计探索》的双层架构。方案与决策见 PLAN.html，实施中的验证与偏差见 implementation-notes.md。

1. 安装与使用

1.1 一次性安装

pnpm install
pnpm build            # 构建守护进程、Worker 侧 MCP server 与审批钩子，并复制进 router-mod/daemon/
pnpm setup:router     # 注册本仓库为本地插件 marketplace，并只在 router/ 目录启用插件
code router           # 用 VSCode 打开 Router 工作区，在里面打开 Claude Code

setup:router 做三件事：写 router/.claude/settings.json（Router 用 sonnet，启用插件）；执行 claude plugin marketplace add <本仓库>（用户级登记）；在 router/ 下执行 claude plugin install agentd-router@kid551-agentd --scope project。撤销用 claude plugin marketplace remove kid551-agentd。

开发模式和 GitHub 安装二选一：这里把市场 kid551-agentd 登记成本地目录来源，按 README.md 安装是同名的 GitHub 来源，同一时间只能有一个。两边也共用一个守护进程（端口 7707），两份插件的 daemon/ 不同就会互相判定对方过期。切换时先 claude plugin marketplace remove kid551-agentd，再跑另一边的安装。开发模式读的是工作区现状，PR 合入后要 git pull 才看得到；GitHub 来源在会话启动时自动更新，要试还没合入的改动，用 claude --plugin-dir <worktree>/packages/router-mod 只在当次会话加载。

市场先后叫过 agentd 和 TerenceXie-agentd。脚本可以重复跑：开头先把这两个旧名 marketplace remove 掉（没登记过就跳过），并从 settings 里删掉对应的 agentd-router@…，否则同一个插件会以两个 ID 各加载一次，每个钩子触发两次。跑完把开着的 Router 窗口重开或 /reload-plugins；守护进程和 Worker 不受影响。

要派工的项目放在 ~/.agentd/config.json 的 roots 下（默认 ~/code）。守护进程不用手动启动：打开 Router 会话时插件会自动拉起它。

1.2 日常

  1. 在 Router 里说人话派工：「在 acme-flutter 里把列表滚动掉帧修了，先别动数据层」。Router 回「#12 · acme-flutter · 修复列表滚动掉帧 · 已派出」。
  2. 继续派别的，Router 安静等待。
  3. Worker 提问时，Router 会自己开口转述。如果你当时没在跟哪个奏折单聊，就自动进入和这个提问奏折的单聊，输入框上方显示：
    ▶ 单聊 #12 · acme-flutter · 修复列表滚动掉帧 · 它在等你回答
    ▶ Router 待处理 2 · 进行中 3 · 你的话直接发给它
    这时你直接打字，就是在回答 #12，话不经过 Router 模型。答完自动转到下一个在等回答的奏折（等得最久的先来）；没有了才回到对 Router 说。
    一次只答一个。你在回答 #12 时，别的奏折的事件（提问、交付、受阻、失败等）全部先排队：Router 不会转述它们，底栏照样写着 Router 的「待处理 N · 进行中 M」（N 包括你正在答的这一个）。答完 #12，单聊转到下一个提问，Router 这时才转述它；提问都答完、单聊结束后，排着的交付等事件再交给 Router。这样屏幕上最新要你回话的永远是你正在单聊的那一个，不会把给 #13 的回答或一句「收了」误发给 #12。
    每个奏折一个框。Router 回复里每段以「#号 · 项目 · 标题」开头的话（提问、权限请求、交付、受阻、派工确认都一样）各画在一个圆角框里，边框按该奏折当前的状态着色，和面板卡片的边框同一套颜色：黄＝在问你，绿＝待验收，红＝受阻/失败，蓝＝在干，灰＝排队或已不在列表里。颜色本身就告诉你这段要不要回话；旧消息的框会跟着奏折状态变色，比如答完后由黄变蓝。开头不属于任何奏折的话（如「一共两份：」）留在框外；不提奏折的回复照常显示。这只改画法，Router 模型和会话记录里的文字不变。
  4. 想跟某个奏折的 Worker 直接说话（追加要求、让交付后的它接着改）：/ticket 12、/next 或在右侧面板点「单聊」。点「单聊」时，左边会话里讲这张奏折的 Router 段落（以 #12 · 项目 · 开头、画在框里的那一段）边框变橙，顶上标「▶ 单聊中」，和右边单聊中的卡片同色，退出单聊就变回状态色；会话底部只插一行短提示，比如「▶ 单聊 #12 · …（在干）：往上数第 3 条 Router 回复讲到它，那一段已框成橙色……」，不复制卡片内容（卡片就在右边）。再点「单聊中」退出时插一行「已结束单聊，你的话回到 Router。」。提示行用 $.ui.log：只显示，不进 Router 模型，不写进会话记录，窗口重载后消失。为什么不直接跳过去：VS Code 扩展 2.1.318 里插件做不到，自动跳和点击跳都不行——ui.scroll 只滚底栏和面板；消息里的链接一律 target="_blank"，#锚点 不会页内跳，插件画的元素也不能设 id；聊天视图没开查找框；$.session.append 的 info 级提示 VS Code 也不画。单聊期间打的每句话都直接发给它，直到 /router 或再点一次「单聊中」；它交付（就绪）、被收或被停时单聊也自动结束：有别的提问在排队就接着单聊那个提问，没有就回到 Router，你接着说的「收了」交给 Router。受阻或失败的不自动结束，方便你在单聊里直接批准。单聊里临时想对 Router 说一句：/r 你的话。
  5. Worker 交付后，面板「待我处理」里出现该奏折。面板里每张进行中的奏折是一张圆角卡片，卡片内上下左右都留了空白，分组之间的间隔比卡片之间更大：边框和左上角的编号徽标用状态色（黄＝在问你，绿＝待验收，红＝受阻/失败，蓝＝在干，灰＝排队；单聊中的那张边框变橙），标题加大加粗；第二行是项目标签（每个项目固定一种颜色，同一项目一眼认出）、状态和「几分钟前」；下方是待答问题（附可选项）或「最近消息」的全文，按 Markdown 渲染。「最近消息」是 Worker 或 agentd 对你说的最后一句：汇报、提问、权限请求、交付、受阻、失败、卡住、异常退出，按时间以最新一条为准（你自己的回答和追加指令不算；启动失败也不算，免得重试成功后还挂着旧原因）；问题挂着时只画问题，不重复；你答了之后，如果「最近消息」正是那个问题，下面多一行灰字「你答：…」（经 Router 转答、面板上点批准/拒绝、单聊里直接回答都算；权限请求只写「批准」或「拒绝」；问题带选项、而你只回了一个选项号，比如「B」「选 2」「b。」，就写成那个选项的全文，比如「B. 两边都做」，带了别的话的回答照原话；超过 200 字截断，全文在事件流里）。MR 奏折待审时你同意开 MR（面板上点「开 MR」或对 Router 说），那条交付说明下面写「你答：开 MR」；收、停、重试、恢复不写。不管哪种回答，Worker 一有新消息就换成新的，不再带旧回答，追加指令不算回答、也不会把它挤掉；待验收的奏折这一块叫「交付说明」。「在干」的卡片在「最近消息」下面多一块「实时动作」（单独的小标题，和完整的最近消息分开，免得被当成截断了的汇报）：Worker 会话里最后两条动作（它说的话，或 ▸ 工具 做什么，如 ▸ Bash Run the tests），每条压成一行、超过 120 字截断，Worker 每做一步就换掉，再一行「● 最近动作 14 秒前」；超过 5 分钟没有新动作，这一行变黄写「⚠ 已 N 分钟没有新动作」。数据来自守护进程 GET /activity：只读会话记录文件末尾 256KB、文件大小没变就用缓存；mod 每 2 秒轮询一次，只在有「在干」的奏折时才请求，并每 10 秒推一下时间，让「几秒前」持续走动而不是停在上一次的数字。已结束的奏折不画卡片，只留标题行和「打开」；这一栏按编号倒序排（新的在上），每页最多 10 张，超过 10 张时底部出现「上一页 / 第 x / n 页 / 下一页」，页码记在会话 atom endedPage 里，奏折过了 24 小时被移出、总页数变少时自动落到最后一页。满意就点「收」或对 Router 说「12 收了」。收会同时停掉 Worker 进程；收了还想改，就派一张新奏折。
  6. 「打开」：Worker 还活着时，用 AppleScript 开一个 iTerm2 窗口执行 claude attach <bgId>（第一次会弹 macOS「允许控制 iTerm」的授权，点允许），挂到正在后台干活的那个进程上，不另起副本。关掉窗口不影响 Worker。Worker 已结束（收/停）时，改为在 VSCode 里打开它的会话记录来读。
  7. 卡片的按钮分三层，主次一眼可见：以前一张卡片把单聊、批准、拒绝、打开、复制、展开、开 MR、放弃、重试、停全排成一行同样的按钮，看不出该按哪个。现在按「这张卡要你做什么」分层，代码在 hooks/register.tsx 的 actions(t)：
    1. 主操作（variant="primary"，强调色）：每张卡至多一个，由状态决定。要权限的是「批准」（「拒绝」紧跟其后，用普通按钮）；在问你的（非权限）是「单聊」，因为答问要在单聊里答；待审的 MR 奏折是「开 MR」；待交付、没有 worktree 的是「收」；失败或受阻的是「重试」。进行中和排队的没有主操作。
    2. 次操作（普通按钮）：「单聊」（不是主操作的时候）、「打开」，都是进入这个 Worker 的方法。
    3. 暗色文字链接：「复制 · 放弃 · 停」，放在最后、用 · 隔开。这些操作不常用或者有风险，不该和主操作一样醒目；一直显示，不藏进「⋯」或悬停，是为了不多一次点击。它们不是 Button，而是 textLink 画出的可点 Markdown 链接（[复制](https://agentd.invalid/copy-12) + onLinkPress，key 仍是 copy-<id> 等）。原因是 VS Code 扩展（2.1.318）不认 plain 和 variant，每个 Button 都画成带框的按钮，CSS 是 padding: 0 var(--app-spacing-medium)：框的上下没有任何内边距，字贴着框，mod 也调不了。一张卡片上框一多就显得拥挤。可点的 Markdown 链接是 VS Code 唯一不加框的可按控件，所以轻量操作全部改成链接，框只留给主操作和次操作。代价：终端里这些链接只能在全屏模式下用鼠标点，不能用 ctrl+x tab 聚焦后按 Enter；VS Code 里鼠标悬停会显示占位的 https://agentd.invalid/…（.invalid 永远解析不到，万一被打开也去不了任何地方）。Markdown 根元素在 VS Code 里是 width:100%，所以 textLink 在外面包一层 Box，让它收窄到链接本身的宽度，不然没法靠右，也没法和按钮排在同一行。
    确认态的代价写成单独一行：第一次点「放弃」或「停」后，链接变成「确认放弃」/「确认停止」（不再暗），操作行上方多一行警告色的「再点一次「确认放弃」：会删掉 worktree 和分支」。以前把这句话塞在按钮标签里，一下就把整行撑爆。已结束奏折那一行的「打开」、长消息的「… 展开全文 / 收起」也是同样的暗色文字链接。已结束的奏折不画框，只有两行：标题一行；项目、状态、几小时前一行，「· 打开」（停了的还有「恢复」）接在这一行末尾，不单独占一行（单独一行时，隔开会离得太远，贴紧又挤）。两张已结束的奏折之间空一行，和卡片之间的间隔一样（空两行显得太松）。
    「进行中」的极简显示：「进行中」标题行最右边有一个暗色链接「极简显示 / 完整显示」。默认是完整显示，也就是上面那种带框的卡片。切到极简后，这一组的每张奏折都按已结束奏折的样子画成两行：标题一行；项目、状态、几分钟前、「· 单聊 · 打开」一行；在干的奏折下面再加一行「● 最近动作 N 秒前」，安静超过 5 分钟就变成警告色的「⚠ 已 N 分钟没有新动作」。最近消息、实时动作的两行、复制和停都不画，要用的时候切回完整显示。只有「进行中」受这个开关影响，「待我处理」始终是完整卡片，因为那里是要你动手的。这个选择记在会话 atom isWorkingBrief 里，session.start 不清空它，/reload-plugins 之后仍然保留。宿主的竖向间距只能按整行算（xs/sm 换算出来是 0 行，VS Code 里一个数字就是一个 lh），所以没有比一行更细的间距可选。状态行（项目、状态、时间和末尾的链接）放不下时会折行。VS Code 里 gap 同时是左右和上下的间距，一折行就会空出一整行，所以面板里所有横排的 Box（标题行、状态行、操作行、按钮组、分组标题、翻页）都只用 columnGap，不用 gap。终端里横排默认不折行，看起来没有区别。这条规则有测试守着；每个「· 链接」由 dotLink 包成一个整体，折行时圆点跟着链接走。主操作和次操作按钮的上下内边距仍然是 0，要等扩展修复。
  8. 「复制」与长消息折叠：VS Code 里面板上的字用鼠标选不中。这是宿主的限制：Claude Code 扩展的 webview 在根节点上设了 user-select: none，对话里的消息行各自又打开了选择，插件面板的容器没有；plugin API 的 Box/Text/Markdown 也没有样式或可选中之类的属性，mod 改不了它。卡片本身没有点击处理，不是点击吞掉了选择。所以每张进行中的卡片多一个「复制」按钮，用 $.ui.copy 把卡片上的字全部写进剪贴板（VS Code 里走 vscode.env.clipboard，终端里和 /copy 一样）：#号 · 项目 · 标题（状态），然后是「它在问你 / 它要权限」和问题、可选项，或者「最近消息 / 交付说明」和 Markdown 原文，以及「你答：…」，内容由 hooks/text.ts 的 cardText 拼出。复制完会弹提示「已复制 #12 · …」，失败时提示「没能复制（原因）」。已结束的奏折没有这个按钮。
    长消息折叠成四行：「最近消息 / 交付说明」确定超过四行时只露四行（Box height=4 overflow="hidden"，VS Code 里是 4lh，终端里是 4 行；行数是 hooks/text.ts 的 FOLD_ROWS，起初是 2，用户觉得藏得太多，改成了 4），折叠开关只有一个，放在文字被截断的地方，学 Claude Code 的「… +N lines」，不再放在操作行里：折叠时四行正文下面靠右有一行暗色的「… 展开全文」（外面包一层 Box justifyContent="flex-end" marginTop={1}：用户要放在右下角，并且和正文隔开一行，不要贴在一起），展开后同一处变成「收起」。小标题「最近消息 / 交付说明」始终是普通文字，不能点。曾经试过把小标题也做成 ▸/▾ 开关，结果上下两个入口互相打架，而且 VS Code 显示的是按钮的 label，不是子元素，所以去掉了。复制始终复制全文。待答问题和权限请求不折叠，需要你操作的内容总是全文显示。「你答」也不折叠，放在折叠区下面。宿主不告诉 mod 渲染后有多高，VS Code 又是比例字体，所以「是否超过四行」只能按下限估算（isLong）：每个 Markdown 块（段落、列表项、标题、引用行、表格行、代码行）至少占一行；段落按最窄字宽算，CJK 1.6 格、其他 0.45 格，标记符号不算，再除以卡片能有的最大宽度（bodyColumns − 4）。这样四行以内的内容一定不会被折叠，也不会出现点了「展开」内容不变的情况；代价是实际四到五行的内容可能不折叠、全文显示。展开状态按奏折记在会话 atom unfolded 里，值是展开那一刻的消息原文：来了新消息就对不上，自动折回；/reload-plugins 或重开会话时 session.start 会清空它，全部恢复折叠。
  9. 权限审批：Worker 用 --permission-mode auto，大部分操作由自动审查放行。被审查拒绝的那一步（比如 git commit）不会让奏折直接失败，而是变成一个「权限请求」送到 Router：卡片上写「它要权限」，列出命令和拒绝理由，带「批准」「拒绝」两个按钮；也可以在单聊里直接打「批准」。批准只放行这一次、这一条完全相同的调用，10 分钟内有效。
    已经以「受阻」交回的奏折（比如卡在 git commit），在单聊里直接打字即可，比如「批准提交并开 MR」：这句话会作为 Worker 自己会话里的用户消息送进去，审查认它（见 3.7）。
  10. 「重试」：受阻或失败、且 Worker 有会话的奏折，点「重试」会停掉旧 Worker，用 claude --bg --resume <会话> 接着原对话重启（带上审批钩子），让它把上次被拒的那一步再做一次——这一次的拒绝会变成权限请求转给你。没启动过 Worker 的（例如目录未信任）仍是重新排队。
  11. 「恢复」：你停掉的奏折（已停），在「已结束」一栏里有「恢复」按钮，Router 也可以用 resume 工具。Worker 接着原会话重启，第一句收到的是「你被用户中途停止过，先只读自查现场，用 report 汇报做到哪了，再用 ask 问下一步，回答之前不做任何写操作」。已收的奏折没有恢复：收＝验收结束，要改就派新奏折。

命名：界面上叫「奏折」，提示词、Worker 看到的文字和代码里叫 ticket。

3. 机制原理

3.1 PDF 机制在这里的落地

PDF这里
Router 不执行、只路由插件的 tool.call 钩子在 Router 会话里拒绝 Bash、Edit、Write、NotebookEdit、Agent，也拒绝 Read、Grep、Glob、WebFetch、WebSearch——Router 连代码都不读，要看什么就派奏折。Router 只有 12 个 agentd 工具。
批处理（Batching）插件每 2 秒拉一次事件流。需要人处理的事件先入队；Router 不在推理、且 1.5 秒内没有新事件时，整队合并成一条「[agentd] N 条新事件」注入，Router 一轮处理完。
Inline & Spill注入的每条事件只带奏折头和 ≤300 字摘要，被截断时注明。全文留在库里。
局部性 Inline提问、受阻、失败、卡住、退出这几类事件额外带上该奏折在它之前的最后一条进展汇报（同样 ≤300 字），Router 转述时知道 Worker 做到哪了，不必先 read。就绪不带（它本身就是结果）；单个奏折的 read events 不带（进展已在列表里）。
链式召回read 工具由浅到深：summary（任务、最近消息、待答问题；两者相同时只列待答问题；最近消息是你答过的问题时，下一行附「你答：…」，和面板一致）→ prompt（任务原文全文）/ events（事件全文）→ transcript（Worker 会话）。每一层都按 Inline & Spill 返回，凡是截掉的部分都写明下一次 read 该带的参数，Router 照着读就行，不用猜：
  • summary 里的任务超过 1200 字就截断，附「共 N 字，read ticket=12 what=prompt 取全文」。
  • events 一页 50 条（limit 可调）。更早还有时，第一行写「更早还有：read … before=事件 id」。
  • transcript 一页 20 条，每条最多 600 字。截断的那条附「read … row=N 取全文」；更早还有时，同样给出 before=。
奏折之间也连成链。派工时带 follows=旧号，表示这张接着那张做；两张的 summary 互相列出（「接续自：#4 …」「后续：#9 …」），下一跳的号就在结果里。find 按关键词（标题、任务、最近消息）或项目查历史奏折，已结束的也在内，最新的在前。用户隔天提起旧任务时，Router 从这里进入这条链。
长程记忆事实源是 SQLite，不是 Router 的 transcript。会话首条消息附带奏折总览；compact 时追加「保留未结束奏折与单聊对象」的指令，压缩完成后的下一条消息重新附带一份从守护进程现取的总览，不靠摘要记住奏折状态。
订阅直通（Fast Path）单聊时你的话由插件直接送给 Worker（有待答问题就是答案，否则是追加指令），返回 { drop } 不进 Router 模型，同时在 Router 对话里记一行「用户已直接回答 #12…」或「用户直接对 #12 的 Worker 说…」，保持 Router 的上下文完整。送不到时这句话改交 Router，并附上原因。
Worker 不直接对人说话Worker 的 AskUserQuestion 被禁用，系统提示要求只用三个 agentd 工具对外。
持久与自愈Worker 是 claude --bg 后台会话，不依赖 VSCode。守护进程每 3 秒对账：Worker 进程消失（claude agents 条目没有 pid）且没 done 记为失败；Worker 空闲超过 45 秒仍在 working 记为 stalled。

3.2 一个问题的往返（非阻塞，PDF §4.1 的异步 ReAct）

  1. Worker 调 mcp__agentd__ask。MCP server POST /tickets/12/ask 建问题，奏折进入 asking，工具立即返回「问题已送出，不用等」。
  2. Worker 只做不依赖答案的只读准备，没有可做的就结束本轮，不调 done（done 会撤回问题）。asking 的奏折不算 stalled。
  3. 插件拉到 ask 事件，入队；没有单聊时自动单聊 #12；Router 空闲后注入，Router 转述。
  4. 你在单聊里打字（或 Router 调 answer）。插件 POST /tickets/12/answer 记下回答，奏折回到 working；接口返回 hadWaiter: false，插件用 $.session.send 把「【agentd ticket #12 回答】…」送进 Worker 会话。Worker 空闲则约 1 秒后开新一轮；正在跑工具则等这次调用结束，和工具结果一起读到（实验 S6）。送不到时如实报告「回答已记下，但没送到」。
  5. 提问期间也能追加指令：message 照常送达，奏折保持 asking，问题不撤回。
  6. 问题没答完奏折就被收、停或 Worker 退出时，问题自动撤回。
  7. 权限请求不同：钩子必须返回一个决定，所以仍是阻塞的，循环 GET /questions/:id?wait=25；答复接口对它恒返回 hadWaiter: true，插件不发消息。Worker 停在钩子里时 message 会被拒绝，请用 answer。

3.4 给 Worker 追加指令

message 工具先 $.session.send 把话送进 Worker 会话，送达之后才 POST /tickets/:id/message 记录并把奏折推回 working。送不到（Worker 会话已不在）直接报错，奏折状态不动——否则会出现「奏折显示进行中、Worker 其实什么都没收到」。

3.5 权限审批

Worker 启动时带 --settings，里面挂三个钩子，都调用 agentd-hook.mjs（和守护进程一起构建、复制进插件）：

钩子何时做什么
PermissionDeniedauto 审查拒绝了一次调用把命令和拒绝理由作为 kind: permission 的问题 POST /tickets/:id/ask，带上这次调用的 grantKey（工具名 + 参数，去掉 description），然后长轮询等你回答。批准 → 输出 retry: true，Worker 原样再调一次；否则什么都不输出，拒绝照旧成立。
PreToolUse每次工具调用前只有标记文件 ~/.agentd/mcp/<id>.grant 存在时才启动 node，POST /tickets/:id/grants/take。守护进程手里有与这次调用 grantKey 相同、未过期的批准 → 消耗掉它并输出 permissionDecision: allow。
PermissionRequest需要人点批准的弹窗（auto 模式下少见）同样转成权限请求，按你的回答输出 allow / deny。

批准由守护进程记账（内存里，10 分钟过期，一次一用），标记文件只是「此刻有没有待用的批准」的快速判断，Worker 自己写这个文件也拿不到放行。你的回答只有「批准」「准」「同意」「可以」「ok」这类明确的肯定词才算批准，其余一律当拒绝。

3.6 重试 = 接着原会话重启

钩子只能在 Worker 启动时挂上。旧版本启动的、或已经交回 blocked/failed 的 Worker，「重试」走 relaunch：先 claude stop 旧进程，再 claude --bg --resume <sessionId> 带上新的 settings 和一句「从上次停下的地方继续，被拒的那一步原样再做一次」。必须先停：对运行中的会话 --resume 会开出第二个进程。

恢复（resume）与重试分开。两者都走 relaunch，但前提和送给 Worker 的话不同：重试针对 Worker 自己交回的 blocked/failed，让它把被拒的那一步再做一次；恢复针对你中途叫停的 stopped，Worker 不知道自己被打断，现场可能是半途，所以只让它自查、汇报、提问。stopped 已经释放了项目，恢复前要重新检查：同项目没有别的非 worktree 奏折占着、Worker 没满、目录还在、有会话可接，任一不满足就拒绝并说明原因。恢复启动的几秒里，同项目的排队奏折不会被同时拉起（launchQueued 把正在启动的奏折的项目也算作占用）。对已停的奏折 retry 或 message 会直接提示「用恢复」，不再给出「Worker 还在」这种误导。

3.7 单聊里对受阻奏折说话 = 在它的会话里亲口说

Worker 的自动审查只认它自己会话里的用户消息。插件 $.session.send 发过去的是「另一个会话发来的消息」，ask 的回答是工具结果，两者里的「批准」审查都不认，所以 #6 这类卡在 git commit 上的奏折，从 Router 转达多少次批准都没用。

因此：单聊一张 blocked/failed 且有会话的奏折时，你打的字不走 session.send，而是 POST /tickets/:id/say：守护进程先停旧进程，再 claude --bg --resume <会话> "<你的原文>"。这句话成了那个会话里的用户消息，和你 attach 进去亲手打字等价，里面的批准审查会认。只有 prompt.submit 里你本人的输入走这条路；Router 模型调 message 工具转达的话，永远是普通的会话间消息。进行中（working/asking）的奏折不走这条路，免得打断它正在跑的一轮。

3.3 派工

cd <项目> && claude --bg --mcp-config ~/.agentd/mcp/12.json --model opus \
  --allowedTools mcp__agentd__report,mcp__agentd__ask,mcp__agentd__done \
  --permission-mode auto --settings '<审批钩子>' --disallowedTools AskUserQuestion \
  --append-system-prompt "<Worker 规则>" [--resume <会话>] -n agentd-w-12 "【agentd ticket #12】…"

只读奏折多一个 --disallowedTools AskUserQuestion,Edit,Write,NotebookEdit。MR 奏折的 cd 目标是守护进程先建好的 worktree，不用 claude --worktree：那样会基于本地 HEAD，而 MR 必须基于最新的 origin/main。

3.8 并行派工：只读奏折与 MR 奏折

原来同一项目同时只能有一个 Worker，因为它们都在同一个目录、同一个分支上写。现在按「写不写」「写在哪」分三种：

奏折在哪干占不占项目怎么结束
只读（Router 派工时 readonly: true）项目主目录不占，也不被占用拦住ready → 收
MR 项目里的写入奏折自己的 worktree <项目>/.claude/worktrees/agentd-<id>-<戳>，分支 agentd/<id>-<戳>，从最新 origin/main 拉出不占待审 → 开 MR → 合入后自动结束并清理；或「放弃」
local 项目里的写入奏折项目主目录、当前分支占，到收或停为止ready → 收（不变）

哪些项目是 MR 项目，由 ~/.agentd/config.json 的 projects 按路径指定（6.1），没写的都是 local。只读奏折和 MR 奏折都照样受 maxConcurrent 限制。

配成 mr 的项目，派工时守护进程还要在本地看一眼仓库（lanes.ts 的 probeOrigin / whyLocal，只读本地，不联网）：没有 origin、本地没有 origin/main、或 origin 在 github.com 上而 owner 不在 githubOwners 里，这张写入奏折就退回 local（主目录、串行），Router 拿到的派工结果后面附一句原因。所以整个 GitHub 目录设成 mr 也安全：master 分支的、没远端的、别人项目的克隆都照旧串行。已派出的奏折不受影响，它是不是 MR 奏折在派工那一刻定下。

MR 奏折的一生：

  1. 派工：守护进程 git fetch origin main，建 worktree 和分支，把 Worker 起在 worktree 里。Worker 的规则 3 写明分支名、不碰项目主目录、依赖自己按项目文档准备。
  2. 做完先交回：Worker 不 commit 不 push，done(ready)。面板显示「待审」，按钮是「开 MR」「放弃」，没有「收」。
  3. 开 MR：你点「开 MR」（或对 Router 说），插件先记 open_mr，再把「【奏折 #N 开 MR】…」送进 Worker 的会话；没送到就调 /open_mr/undo 撤回，奏折回到「待审」。你同意时附带的话（比如「先验证，然后开 MR」），Router 写进 open_mr 的 text，接在固定那句后面（「用户另外交代：…」）一起送去，不会另用 message 转达。开 MR 只认 agentd 的记录（mr_opened_at），不认消息里的字：谁都能在 Worker 会话里打出「【奏折 #N 开 MR】」，agentd 却不知道（#39 就是这样合入后收不了尾，#27 也卡过）。没有记录时 done(merged) 会被拒。所以 Worker 收到这条消息、或有人让它开 MR、commit、合入时，先调 mr_consent（dsh：superagent_mr_consent）查记录。已记下就开；没记下时，奏折若还是「待审」就不调 report/done，只在会话里回一句请你点「开 MR」，免得奏折离开待审、按钮消失；奏折若已被消息叫醒（working），就照做别的要求，最后 done(ready) 交回，按钮重新出现。回答文案在 lane-rules.ts 的 mrConsentAnswer，两边宿主共用。已经开了 MR 之后在单聊里批准提交之类的话不受影响。dsh 的 superagent_open_mr 同样带 text。Worker 接着 commit、push、开向 main 的 MR（合入后删除源分支）。怎么开 MR、怎么设自动合并，照目标项目 AGENTS.md / CLAUDE.md 的合并说明做，项目文档优先于合并脚本；合并人以用户本人为准，项目文档没要求就不用机器人令牌合并。项目文档没写怎么合并时才退回项目的自动合并脚本，并在汇报里写明合并人会是谁。然后盯着流水线：失败就修，落后就 rebase，只动自己的 MR。规则只写原则和优先级，不写某个项目的具体命令。origin 在 github.com 的项目，规则 3 b 换成 GitHub 版：MR 就是 PR，项目文档没写时用 gh pr create 开、gh pr merge --auto --squash --delete-branch 设自动合并（gh 登录的是你本人的账号；仓库没开自动合并就等检查过了直接合，不用 --admin 绕过），gh pr checks --watch 盯着，合入后源分支还在就自己删掉；gh 没登录就 ask 你去 gh auth login。其余主机一律按 GitLab 的原文，acme 一字不变。
  4. 合入：Worker done(merged)。守护进程不信口头：先 git ls-remote 看 origin 上这个分支还在不在，还在就拒绝（MR 没合，或没设删源分支）。通过后奏折进 done，停掉 Worker，删 worktree 和本地分支。
  5. 放弃：合入前任何时候点「放弃」（第二下确认），或 Router 带 discard=true 收。直接删 worktree 和分支。不带 discard 的收会被拒，提醒先跟你确认。

清理规则（偏差 P4）：合入后的 worktree 若还有未提交改动就保留，面板上记一条「保留了 …」等你看；放弃和 dropped 直接删。分支一律 git branch -D，删前把分支头存到 refs/trash/<分支名>，提交不会真丢。守护进程启动时补扫一遍上次没清干净的。

会话 ID 由 --bg 自己分配，守护进程随后从 claude agents --json --all 按名字取回，用于 transcript 读取和 VSCode deeplink。

4. 微妙之处

  • 目录必须先被信任。claude --bg 在未信任的目录直接拒绝，父目录的信任不继承；但已信任仓库的 worktree 能直接起，所以 MR 奏折的 worktree 不用另外信任。这种奏折会进入 failed，原因写明「请在该目录运行一次 claude 并接受信任提示」，处理后点「重试」。agentd 不代你写信任记录。
  • 注入可能被拒。会话启动后你还没说过话、或你按 Esc 打断之后，引擎不允许插件开新回合。此时事件留在队列，band 显示「N 条新事件待送达」，随你的下一句话作为附加上下文一起给 Router。
  • 焦点从不被抢。焦点只在为空时自动给提问的奏折。否则你以为在回答 #12，却被送到了 #13。多个奏折同时提问时，Router 会一个一个来，你用 /next 切换。
  • 收即停。每个空闲的后台 Worker 都是一个常驻的 Claude Code 进程。「收」在关闭奏折的同时执行 claude stop，否则空闲 Worker 会越积越多。会话记录仍在磁盘上。停失败（Worker 已不在）只记日志，不影响关闭。
  • local 项目的写入奏折串行，占到 close/stop 为止。同一项目主目录里同时只有一个写入 Worker。交付（ready/blocked/failed）不让出项目——Worker 还在那个工作区，你随时可能叫它接着改。只有「收」或「停」才放下一张排队的进去。只读奏折和 MR 奏折不受这条限制（3.8）。
  • 只读靠拿掉写工具 + 规则，不是 plan 模式。后台会话里 plan 模式对写操作、甚至对 agentd 自己的 report 都弹确认，没人能点，Worker 就卡住（偏差 P1）。只读 Worker 没有 Edit / Write，Bash 只靠规则约束。
  • MR 阶段 Worker 要一直挂着。等流水线可能几十分钟。Worker 把查 MR 状态的命令（项目文档给的方式，或退回时的自动合并脚本）放后台跑、前台定期看输出，本轮不结束；它停下不汇报，照常会在 45 秒后被判 stalled。
  • MR 奏折结束后不能再发消息。合入、放弃、dropped 都停掉 Worker 并删 worktree；要接着改就派新奏折。
  • Worker 存活只看 pid。claude agents 对空闲的活会话也会报 state: done；真正结束的会话是没有 pid 字段。守护进程只认后者，不然正在等你答复的 Worker 会被误判为退出。
  • 单聊跟着奏折走。单聊的奏折交付（就绪）、无事可做、合入、被收、停或从列表消失，单聊自动结束，你的话不会发给一个已不存在或已经交差的 Worker。「交付」按这一轮新到的 ready 事件判断（poll()），不看状态：对一张早已交付的奏折开单聊让它接着改，不会被立刻踢回 Router。受阻、失败不结束（你多半要在单聊里亲口批准，见 3.7）；单聊奏折还有待答问题或权限请求时也不结束。结束后统一走 endChat：有别的奏折在等回答就交给等得最久的那个，没有才回到 Router。只有你主动离开（/router、面板「单聊中」）一律回 Router，即使有提问在排队。
  • 自动单聊只管一问，答完传给下一问。提问奏折自动打开的单聊，在它的问题消失时结束：你在单聊里答了、在面板上批了、经 Router 的 answer 答了、问题被撤回，或者奏折结束了。结束后单聊交给等得最久的下一个提问（按 updatedAt），没有就回到 Router。判断放在 refresh() 里，所以不管从哪条路答的都生效。你自己打开的单聊（/ticket、/next、面板按钮）答完也保持（那是你主动选的对象），直到它交付、被收或被停（见上一条，结束时同样交给下一个提问），或者你自己结束它。单聊从不被抢：新的提问不会把你从当前单聊里拉走。
  • 回答期间其他奏折的事件全扣。takeEvents() 在你正回答某个奏折时，把其他奏折的事件全部留在队列里。队列里本来就只有要你回话的事件（提问、交付、受阻、失败、无事可做、停下没汇报、异常退出、启动失败；进度不进队列），每一种都可能让你接一句话，而这句话在单聊里会发给正在单聊的 Worker。正在回答的那个奏折自己的事件不扣。批量注入和「随你下一句话附带」两条路都走 takeEvents()，按事件 id 取走，不按位置，因为轮询和回合结束都可能同时往队列里写。你用 /router 主动离开单聊时，排队的提问在下一次轮询时一起交给 Router。
  • 分框靠 Router 的写法。切分规则在 hooks/text.ts 的 ticketSections：一行以 #12 · 项目 · 开头（前面可以有 1. 、- 、### 、** 这类 Markdown 标记），就开始一个新框，直到下一个这样的行；行中间提到的 #号不算。依据是 Router 提示词要求「每个 ticket 一段，以 #号 · 项目 · 标题开头」。模型偶尔不照写时，那段话就不进框，照常显示，不会画错。
  • 守护进程会过期。它是常驻进程，pnpm build 后仍跑旧代码。插件问 /status?script=<插件自己的 daemon/agentd.mjs>，守护进程比较那个文件和自己启动时那份的内容哈希（sha256），不比路径也不比 mtime：从市场装的插件每个版本放在各自的缓存目录，新版本是另一个文件，守护进程启动用的那份原样不动，比 mtime 永远发现不了；比内容也让 pnpm serve（跑 dist/ 里那份）不会被误判。插件启动时发现过期会提示你 /agentd restart。restart 先发 /shutdown；对方没有这条路由（早期构建）或 5 秒内没退，就按 /status 报的 pid 发 SIGTERM；还在就明说失败，不会假报「已在线」。确认换成功：/agentd status 里的 pid 变了。
  • transcript 不一定在「cwd 转义」目录里。本机上 /private/tmp/…/proj 的会话落在 -private-tmp-agentd-spike-proj 下，所以按 sessionId 全目录搜索。
  • VSCode 的 deeplink 只在会话所属文件夹的窗口里生效。已结束奏折的「打开」先 open -a "Visual Studio Code" <项目> 聚焦那个窗口，再发 deeplink。活着的 Worker 不走这条路：deeplink / --resume 会对同一会话另起一个进程。
  • 权限审批尚待实测的两点。①PreToolUse 返回 allow 能否压过 auto 审查对同一调用的再次拒绝；②PermissionDenied 钩子等你回答时（最长 24 小时）Worker 是否真的停在那里。单元与端到端测试只证明 agentd 这一侧的往返正确。若 ① 不成立，备选方案是 Worker 改用 acceptEdits + PermissionRequest 钩子。
  • 同一时刻只能挂一个权限请求。奏折处于 asking 时第二个被拒的调用不再提问，拒绝照旧成立，Worker 按规则换路或交回 blocked。批准存在内存里，守护进程重启会丢——后果只是那一步再被拒一次。
  • 权限模式要一致。跨会话消息在接收方权限模式不同时会被扣下等批准。Router 与 Worker 都用 auto。
  • 守护进程的生命期。插件以 serve --detach 启动它，它脱离会话独立运行；没有进行中的奏折且 30 分钟无请求时自行退出，下次打开 Router 时再被拉起。Worker 在它不在线时调用工具会得到「agentd 不在线」，ask 会自动重连等待。
  • mod 的写法限制。引擎静态分析 mod：不能把 $ 作为参数传递，atom 的 plugin 名必须是字面量，同一事件不能注册两个无 matcher 的钩子，命令名不能与内置命令重名。
  • transcript 一条的号是它在文件里的字节偏移。Claude Code 的会话 jsonl 只追加不改写，所以偏移稳定：row= 直接定位到那一行读，不用扫全文件。before= 从那个偏移往前、每次 1 MB 倒着读，凑够一页为止，不再受旧版「只看最后 1 MB」的限制。单行比 1 MB 还长的（巨大的工具结果）整行跳过，这种行本来也不显示文字。偏移不是行首时，row= 返回 404。
  • follows 写错不挡派工。写了一个不存在的号，奏折照样派出，只是不记接续关系；返回里附一句「没有 ticket #N，没记接续关系」让 Router 知道。follows_id 列没有加外键：派工时已经核对过，奏折也从不删除，而且 SQLite 里被外键用到的列以后再也删不掉。
  • find 是 LIKE 扫表。一张奏折对应一件你交代的事，表很小，建索引不划算。% 和 _ 按普通字符匹配。
  • 新插件配旧守护进程照样能读。events 和 transcript 的返回从数组改成了 { events|rows, more }。插件遇到旧守护进程回的数组照常显示，只是没有「更早还有」这一行。find 和 row= 需要新守护进程，碰到旧的会报「没有 GET …」，/agentd restart 换上新构建就好。
  • 直通的提示文案。直通时引擎会显示一行「Prompt dropped by a hook: 已直通 #12 …」。这是引擎对 { drop } 的固定前缀，不是出错。

5.1 公开仓库的隐私规则

规则写在 AGENTS.md，CLAUDE.md 引用它，所以在本仓库里起的 Claude Code 会话（包括 agentd 派来的 Worker）都会读到。要点：不提交密钥、个人邮箱、本机绝对路径、内网主机、别的私有项目的任何信息；举例一律用占位（acme、alice、example.com、~/code）；开发笔记写进 implementation-notes.md，它不进版本库。

机制：pnpm install 的 prepare 把 core.hooksPath 指向 .githooks/，pre-commit 跑 scripts/check-sensitive.mjs --staged，读暂存区里的内容（不是工作区），命中就拒绝提交；commit-msg 用同一套规则查提交信息（提交信息同样会公开）。它查：

  • 常见密钥格式（私钥块、sk-、ghp_、glpat-、AWS、JWT…）和「secret / token / password = 长字面量」；
  • /Users/<名>、/home/<名>、C:/Users/<名>，单字母和 alice 这类占位名放行；
  • 邮箱，只放行 example 域名和 GitHub / Anthropic 的 noreply；
  • git 远端主机，只放行 github.com、gitlab.com、bitbucket.org 和 example 域名；*.ts.net；私网 IP；
  • 文件名：.env*（.env.example 除外）、密钥文件、数据库文件、implementation-notes.md；
  • 提交人与作者的邮箱（git var GIT_AUTHOR_IDENT，环境变量覆盖也算）必须是 noreply 地址——它会随每个提交公开。
  • CI 里另有两步（.github/workflows/ci.yml）：PR 的标题和描述按提交信息的规则扫（它们就是 squash 后的提交信息，PR 一改就重跑）；push 到 main 后用 --commits <before>..<sha> 查新提交的作者、提交人和提交信息。CI 里没有 .sensitive-words，只有通用规则。

微妙之处：规则只能写成通用的，因为把「我的公司名、内网主机名」写进脚本本身就是泄露。这类词一行一个放在仓库根的 .sensitive-words（被 gitignore），脚本运行时读入（在 worktree 里提交时也读主目录那份，agentd 的 Worker 就是在 worktree 里提交的）、不分大小写匹配。真要放行的一行加 sensitive-check: allow 注释。GitHub 上的 squash 合并不经过本地 hook：合并提交由 GitHub 生成，作者取账号的资料名和主邮箱，跟分支上的提交无关，所以账号要开「Keep my email addresses private」，CI 那一步是事后的报警。测试里的样例用字符串拼接，免得测试文件自己触发检查。pnpm-lock.yaml 不扫。

6.4 分享给别人

本仓库本身就是插件市场 kid551-agentd（.claude-plugin/marketplace.json），别人不用 clone、不用 build。

对方需要：Node ≥ 24（守护进程用 node 跑）；git（GitHub 来源的市场靠它 clone）；claude 在 PATH 上（守护进程用它起 Worker）。仓库是公开的，不用 SSH key 也不用登录 GitHub。macOS 以外未验证：「打开」按钮用的 open -a 是 macOS 专用。

安装：照仓库根的 README.md 做（GitHub 首页显示的就是它），一段命令贴进终端即可。VSCode 插件版与终端版共用这套配置。它做三件事：

  1. 建专用文件夹和标记文件 .agentd-router。
  2. 先写 .claude/settings.json，在 extraKnownMarketplaces 里声明这个市场并带上 "autoUpdate": true。
  3. claude plugin install agentd-router --marketplace kid551/agentd --scope project：--marketplace 让一条命令先在用户级登记市场、再装插件；--scope project 往同一个 settings 里加 enabledPlugins，上一步写的条目原样保留（2.1.318 实测）。

为什么第 2 步要在 install 之前手写：第三方市场默认不自动更新，marketplace.json 没有字段能替用户打开，marketplace add 也没有对应参数。官方文档写明 settings 文件里 extraKnownMarketplaces 条目上的 autoUpdate 会被读取，项目级的要在文件夹被信任后才生效。所以把它放进 Router 文件夹的项目设置：只影响这一个市场，也不用碰用户的全局设置。不写的话，每人要手动开一次：/plugin → Marketplaces → kid551-agentd → Enable auto-update。

更新：开了自动更新的，每次会话启动在后台检查新提交，下次会话生效（或 /reload-plugins）。手动更新是 marketplace update 加 plugin update，命令见 README.md。插件更新后守护进程还是旧的，Router 会提示 /agentd restart（见第 4 节「守护进程会过期」）。2026-11-05 仓库历史被重写过；在那之前装的人照常 update 即可：marketplace update 发现本地副本和远端历史对不上会重新 clone（实测）。

发版：改代码 → pnpm check（最后一步 build 会把产物复制进 packages/router-mod/daemon/）→ 连同 daemon/ 一起提交 → push main。三件事让它成立：

  • daemon/ 进版本库。别人装插件时 Claude Code 只 clone 和复制，不会替他们 build。
  • plugin.json 不写 version。用户只有在插件版本变了才拿新副本；不写版本就按提交 SHA 算，每次 push 都是新版本。写了 0.1.0 又不改，用户永远停在旧缓存上。claude plugin validate 会为此报一条警告，是有意的。
  • 过期检测比内容。见第 4 节。

对方访问不了 GitHub（或用 Windows）：pnpm pack:share 在 output/（已加入 git 忽略）生成两个文件，一起发过去即可：

  • agentd-router.zip：git archive HEAD .claude-plugin packages/router-mod，只打包这两处已提交的文件，所以不会带上未提交的改动、.git、node_modules、~/.agentd，也不会带上仓库里的其他文档。这两处如果有未提交的改动，脚本会拒绝打包，避免刚 build 完的 daemon/ 还没提交、包里装的却是旧版本。
  • agentd-router-install.html：从 scripts/share/ 复制过来（源文件进版本库），是写给对方 Claude Code 执行的安装规程，Windows 专用：每一步都写明命令、成功标志、失败时怎么办，并标出要问用户、要用户亲手做的步骤。对方把两个文件放在一起，让 Claude「按这份 HTML 安装」即可。对方会用本地目录作为 marketplace 来源（claude plugin marketplace add <解压目录>）。这种来源没有提交 SHA，插件版本显示为 unknown；升级时覆盖解压目录，再运行 marketplace update 和 plugin update，就会从源目录刷新（已在 macOS 上验证）。
  • Windows 上已知的缺口写在规程第 6 节：「打开」按钮依赖 iTerm2 和 open -a，在 Windows 上不可用；守护进程用 execFile('claude') 起 Worker，要求找到的第一个 claude 是 claude.exe，否则需要设置 AGENTD_CLAUDE；守护进程可能会单独开一个控制台窗口。

告诉使用者的三件事：

  • 标记文件放在专用空目录，别放进代码仓库。Router 会话禁用 Bash / Read / Edit / Write 等工具，仓库里放了标记就在那里读不了也改不了代码；提交进去还会让同事的会话也变成 Router。
  • 别把 AGENTD_ROUTER=1 设成全局环境变量，否则每个会话都是 Router。
  • 一次只开一个 Router 窗口。守护进程全机一个（7707 端口、~/.agentd），所有 Router 共用同一批奏折，没有互斥：两个 Router 会收到同样的问题与交付，都可能去回 Worker。

在普通目录里插件几乎不做事：工具和斜杠命令只在 Router 会话注册，其余钩子见 kit 为空即放行，也不会拉起守护进程。只装在 Router 目录（--scope project）时，别的会话根本不加载它。

7. DeepSeek Harness 版（dsh-superagent）

同一套 Super-agent 的第二个宿主：packages/dsh-superagent 是 DeepSeek Harness（dsh）桌面应用的 profile 插件。Router 和 Worker 都是 dsh 的原生会话，不需要守护进程、MCP 和 CLI 对账。方案与已定决策见 DSH-PLAN.html，验证结论与偏差见 implementation-notes.md 的「dsh-superagent」一节。

7.1 安装与使用

pnpm install

# 卸载：pnpm --filter dsh-superagent uninstall:dsh

  1. 左侧栏出现「Super-agent 奏折」面板。点「打开 Router」进入 Router 会话（放在 ~/.dsh/superagent/router 工作区）。
  2. 对 Router 说要做什么。Router 调 superagent_dispatch 在对应项目里开一个 Worker 会话，Worker 出现在侧栏该项目下，行首有 #号 徽标。
  3. Worker 的提问、审批画在它自己的会话里。Router 会转述并让你去「单聊」：在面板点「单聊」或 band 上的「下一张」，直接在 Worker 会话里回答。你在 Worker 会话里说的话，Router 会以旁注的形式知道。

7.3 机制原理

  • Router 不执行：preset superagent-router 只有 persona、time-context、compaction，没有 shell / fs / web 工具；插件再给它装 9 个路由工具。不能靠 tools.restrict：它只遮全局工具，preset 的工具遮不掉。
  • Worker 是普通会话：经 sessionController.create 创建，和你在界面里新建的会话一样归 controller 所有，插件重载不影响正在干的 Worker。会话 id 在创建前就写进奏折，agent/created 触发时就能认出它是哪张奏折。
  • 批处理：需要人处理的事件（提问、就绪、受阻、失败、卡住、中断、启动失败）入队；1.5 秒内没有新事件、且 Router 空闲时，合并成一条「[superagent] N 条新事件」用 followup 开一轮。Router 正在推理时不打断，等 agent/status 变 idle。
  • Inline & Spill 与链式召回：每条事件 ≤300 字，截断时注明；交回类事件附此前最后一条进展。superagent_read 由浅到深：summary → task（任务全文）/ events → transcript。和 agentd 一样，截掉的部分都写明下一次该带的参数（before、row）；summary 列出接续关系（派工时带 follows）。旧奏折用 superagent_list 带 query / project 找，已结束的也在内。summary 和总览里的「最近消息」与 agentd 同一规则（Worker 或插件说的最后一句，等你处理的提问或审批也算，另含 interrupted；你在 Worker 会话里说的话不算），与「在等你」相同时不重复。
  • 提问与审批只镜像：在 Worker 的 user-questions/request、approval/request 上挂一个只观察的监听，奏折进 asking，next() 结算后回 working。Router 不能替你批准。
  • watchdog：working 的 Worker 空闲超过 60 秒没调 done 记为卡住（受阻），附最后一个动作；插件启动时，working/asking 但会话已不在线的奏折记为中断。

7.4 微妙之处

  • 插件不 import dsh 的包：profile 的模块兜底目录在本机指向旧的源码 checkout，import 进来会是另一份副本。所有 dsh 接口都按结构类型调用（src/host/dsh.ts 顶部）。
  • 模型：Router 和 Worker 都用你当前的默认模型（偏差 1）。按会话指定模型会把你的全局默认改掉，所以没做。
  • 消息来源：批量事件显示为「收到外部事件」（webhook 来源），Router 转给 Worker 的话显示为「收到任务消息」（agent-message 来源）。Worker 被要求不把后者当作权限批准。
  • 收与停：收只结束奏折、停掉正在跑的一轮，会话保留；停可以恢复，恢复时 Worker 先只读自查、汇报、提问。
  • 只读奏折与 MR 奏折：和 agentd 同一套（3.8），共用 packages/agentd/src/lanes.ts 与 lane-rules.ts。worktree 前缀是 superagent（.claude/worktrees/superagent-<id>-<戳>），和 agentd 的不会撞名。插件配置里 projects: { "<路径>": { "delivery": "mr" } } 指定 MR 项目。三点不同：派工时不做 3.8 的本地检查，也不认 githubOwners，规则 3 b 一律是 GitLab 版（偏差 P15）；只读奏折只有规则约束，并且照旧占用 local 项目（偏差 P2）；「放弃」二次确认在面板卡片上。
  • transcript 一条的号是行序号：dsh 会话按消息块排成行（文字一行，工具调用一行），row= 和 before= 用的是这个序号。会话只追加时序号稳定；如果 dsh 压缩改写了会话，旧序号会对不上，那就重新读一次尾部（偏差 R2）。
  • 尚未在真 dsh 里跑过：单元测试和接线测试用的是按安装版接口写的模拟 ctx。装上之后需要确认的点列在 implementation-notes 的 spike 结论里（S1、S3–S7）。
