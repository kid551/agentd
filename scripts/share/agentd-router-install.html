agentd-router 安装规程

平台：Windows · 安装包：agentd-router.zip（与本文件放在同一个文件夹）

给人看的：怎么用这份文件
  1. 把 agentd-router.zip 和本文件放进同一个文件夹，比如「下载」。
  2. 在任意文件夹打开 Claude Code，对它说：
    读一下 C:\Users\你的名字\Downloads\agentd-router-install.html，按里面的规程帮我安装 agentd-router
  3. Claude 会一步步执行，途中会问你两三个问题。有几步只能你亲手做（重启 VS Code、点信任提示），Claude 会告诉你什么时候做。
这个插件目前只在 macOS 上测试过，Windows 上是第一次安装。遇到问题时，让 Claude 按第 6 节整理信息发回给作者。

0. 给 Claude：背景与执行规则

要装的是什么：agentd-router 是一个 Claude Code 插件，以本地目录 marketplace 的形式分发。marketplace 名为 kid551-agentd，插件名为 agentd-router。装好后，用户在一个专用文件夹里打开的 Claude Code 会话会变成 Router：用户用自然语言派活，插件通过本机的守护进程（Node 脚本，HTTP 监听 127.0.0.1:7707，数据放在 ~/.agentd）为每个任务起一个后台 claude --bg（Worker），让它到对应的 git 仓库里工作。这个包不需要 build，zip 里已经带有构建好的 .mjs。

执行规则：

  1. 按 1 → 5 的顺序执行。每一步跑完先看「成功标志」，满足了再进入下一步。不满足就按「失败时」处理；处理不了就停下来，把输出原样告诉用户。
  2. 标着 问用户 的地方必须先问用户、得到回答再继续，不要自己猜。
  3. 标着 用户操作 的地方你做不了，比如重启 VS Code、在 GUI 里点信任，或者在另一个会话里输入斜杠命令。请把要做的事清楚地告诉用户。
  4. 不要修改 zip 里的任何文件，也不要在用户的代码仓库里创建 .agentd-router 文件。
  5. 路径写法：下面用 <HOME> 表示用户主目录，请先用 echo %USERPROFILE%（cmd）或 $env:USERPROFILE（PowerShell）或 echo $USERPROFILE（Git Bash）查出真实值。在命令和 JSON 里一律用正斜杠，比如 C:/Users/alice；Windows 的 Node、tar 和 claude 都认正斜杠，PowerShell、cmd、Git Bash 三种 shell 里写法也一样，可以避开转义问题。
  6. 跨 shell：下面的命令在 PowerShell 和 Git Bash 里都能直接运行。只有一个例外：Windows PowerShell 5.1 不支持 &&，需要切换目录时请分成两条命令，或者把工具的工作目录设好。
名称值
ZIP和本 HTML 同一个文件夹下的 agentd-router.zip
MARKET<HOME>/agentd-market：解压目录，也就是 marketplace 来源。装好后必须一直保留
ROUTER<HOME>/agentd-router：Router 专用的空文件夹
AGENTD_HOME<HOME>/.agentd：守护进程的配置、数据库和日志
DAEMON<MARKET>/packages/router-mod/daemon/agentd.mjs

1. 检查前置条件

node -v
git --version
claude --version
code --version
where.exe claude
项成功标志失败时
Nodev24.x 或更高 问用户 是否用 winget install OpenJS.NodeJS.LTS 和 winget install Git.Git 安装。用户同意后再装，装完让用户重开终端，或者你重新开一个 shell 再检查。
Git有版本号输出
Claude Code有版本号输出你自己就是 Claude Code，这一项应该总能通过。建议运行一次 claude update，因为插件依赖较新的 claude --bg / claude agents。
VS Code有版本号输出告诉用户：Router 建议在 VS Code 的 Claude Code 扩展里使用。如果用户只用终端版，可以跳过这一项。
where.exe claude输出里有一行以 claude.exe 结尾，而且是第一行 守护进程用 Node 的 execFile('claude', …) 起 Worker，不经过 shell，所以运行不了 claude.cmd 或 .ps1（npm 版就是这种）。
  • 一个 .exe 都没有：问用户 能否安装原生版。安装命令是在 PowerShell 里运行 irm https://claude.ai/install.ps1 | iex。这会执行一个远程脚本，必须得到用户明确同意。
  • 有 .exe，但不是第一行：在第 3 步额外设置环境变量 AGENTD_CLAUDE，把它指向这个 .exe 的完整路径。

2. 解压

mkdir "<HOME>/agentd-market"
tar -xf "<ZIP>" -C "<HOME>/agentd-market"

Windows 10 及以后的版本自带 tar，可以解压 zip。如果 MARKET 已经存在（重装或升级），先删掉它再解压，具体见第 7 节。

成功标志：<MARKET>/.claude-plugin/marketplace.json 和 <DAEMON> 这两个文件都存在。

3. 写配置

3.1 项目根目录（必做）

问用户：你的代码仓库都放在哪个文件夹下？可以给多个。agentd 只会在这些目录下面（最深 3 层）找 git 仓库，作为可以派活的项目。
可选，一并问：Worker 默认用 opus 模型。你的账号能用吗？用不了就改成 sonnet。

用你的文件写入工具（不要用 shell 重定向）创建 <HOME>/.agentd/config.json，需要时先建好目录。内容示例：

{
  "roots": ["D:/code", "C:/Users/alice/projects"]
}

需要改模型时这样写：

{
  "roots": ["D:/code"],
  "worker": { "model": "sonnet" }
}

注意三点：

  • 文件必须是 UTF-8 无 BOM。守护进程直接 JSON.parse，遇到 BOM 会报错。PowerShell 5.1 的 Set-Content -Encoding utf8 和 Out-File 都会写入 BOM，不要用。
  • 路径用正斜杠。~/ 开头会展开为用户主目录。
  • 其他字段不要写，用默认值即可：端口 7707，交付方式是在本地 worktree 里完成。

3.2 AGENTD_CLAUDE（仅在第 1 步要求时才做）

setx AGENTD_CLAUDE "C:/Users/alice/.local/bin/claude.exe"

把路径换成 where.exe claude 输出里那个 .exe 的实际路径。setx 只对之后新启动的进程生效，所以第 5 步要让用户完全重启 VS Code。

4. 安装插件

claude plugin marketplace add "<HOME>/agentd-market"
mkdir "<HOME>/agentd-router"
node -e "require('fs').writeFileSync(process.argv[1], '')" "<HOME>/agentd-router/.agentd-router"

然后把工作目录切到 ROUTER，再执行下面这条（--scope project 按当前目录生效）：

claude plugin install agentd-router@kid551-agentd --scope project
检查成功标志
marketplace add 的输出Successfully added marketplace: kid551-agentd
install 的输出Successfully installed plugin: agentd-router@kid551-agentd (scope: project)
在 ROUTER 里运行 claude plugin list能看到 agentd-router@kid551-agentd，Scope: project，Status: enabled
<ROUTER>/.claude/settings.json包含 "agentd-router@kid551-agentd": true
<ROUTER>/.agentd-router文件存在，内容为空

失败时：

  • 提示 marketplace 已存在：先运行 claude plugin marketplace remove kid551-agentd，再重新 add。
  • 安装时找不到插件：检查第 2 步是否解压到了正确位置，marketplace.json 应该在 MARKET 的 .claude-plugin 子目录里，而不是多套了一层文件夹。

5. 自检守护进程，然后交给用户

5.1 自检（你来做）

这一步在 Windows 上实际验证一遍：守护进程能起来、能读到配置、能扫描到项目。

node "<DAEMON>" serve --detach --port 7707 --idle-exit 1800

等大约 2 秒，然后：

node "<DAEMON>" status
node "<DAEMON>" projects --rescan
检查成功标志失败时
status输出 JSON，其中 "ok": true，"projects" 大于 0读 <HOME>/.agentd/logs/daemon.log 的最后 80 行。端口被占用（EADDRINUSE）就告诉用户有别的程序在用 7707；JSON 解析错误就回到第 3.1 步检查 BOM 和格式。
projects --rescan每行一个「项目名 + 路径」，包含用户的仓库列表为空：roots 写错了，或者仓库在 3 层以下，或者目录里没有 .git。把结果给用户看，再修改 roots。

自检通过后关掉这个守护进程。它是你的 shell 启动的，拿不到第 3.2 步刚设置的环境变量。关掉之后，等用户打开 Router 时插件会自动重新拉起它：

curl.exe -s -X POST http://127.0.0.1:7707/shutdown

在 Git Bash 里写 curl 也可以。成功标志：输出 {"ok":true}，再运行 status 会显示「agentd 不在线」。

5.2 交给用户

用户操作：把下面这段原样转告用户，并把里面的路径换成真实路径。
  1. 完全退出 VS Code，包括所有窗口。如果设置过 AGENTD_CLAUDE，必须这样做才会生效。
  2. 重新打开 VS Code，用「文件 → 打开文件夹」打开 <ROUTER>。在终端里运行 code "<ROUTER>" 也可以。
  3. 在这个窗口里打开 Claude Code。如果问你是否信任这个文件夹，选「是」。
  4. 成功的样子：输入框上方有一行状态条，写着 ▶ 对 Router 说 · 待处理 0 · 进行中 0，旁边有一个奏折面板。如果是红色的「agentd 守护进程不在线」，在那个窗口里输入 /agentd start。
  5. 每个要派活的项目，都要先信任一次：在终端里进入那个仓库目录，运行 claude，选「信任」，然后输入 /exit。没信任过的仓库 Worker 进不去，Router 会提醒你。
  6. 试着派一个活。在 Router 里直接说，比如：「在 my-app 里给 README 加一节安装说明」。

6. 已知问题与排查

现象原因处理
面板上的「打开」按钮没反应或报错这个按钮用的是 macOS 专有的 osascript/iTerm2 和 open -a，Windows 上不支持想看正在干活的 Worker：运行 claude agents 找到它的 ID，再运行 claude attach <ID>。关掉这个窗口不影响 Worker。
多出一个黑色控制台窗口守护进程以 detached 方式启动，Windows 可能为它单独开一个控制台不要关它，关了守护进程就停了。它闲置 30 分钟后会自己退出，下次打开 Router 时会再拉起来。
派活后立刻失败，提示里有 EINVAL、ENOENT 或 spawn守护进程找不到可以直接执行的 claude.exe回到第 1 步检查 where.exe claude，按需做第 3.2 步，再让用户完全重启 VS Code，在 Router 里输入 /agentd restart，最后对这个任务说「重试」。
Router 提示某个目录「尚未被 Claude Code 信任」那个仓库没有信任过按 5.2 的第 5 条处理，然后对这个任务说「重试」。

处理不了时，在任意 shell 里收集下面这些信息，连同 Router 窗口的截图一起交给用户，让用户发给作者：

claude --version
node -v
where.exe claude
node "<DAEMON>" status

再附上 <HOME>/.agentd/logs/daemon.log 的最后 80 行。

7. 升级（收到新的 zip 时）

用户拿到新的 agentd-router.zip 后，可以让 Claude 读本节执行。

  1. 删掉旧的 MARKET 目录，再按第 2 步把新的 zip 解压到同一个位置。
  2. 运行 claude plugin marketplace update kid551-agentd。
  3. 把工作目录切到 ROUTER，运行 claude plugin update agentd-router@kid551-agentd --scope project。成功标志：输出 refreshed from source 或类似的成功字样。插件没有版本号，会显示 unknown，这是正常的。
  4. 用户操作 关掉 Router 窗口重新打开，在 Router 里输入 /agentd restart，把守护进程也换成新版本。如果启动时提示「守护进程跑的是旧构建」，也是做这一步。

8. 卸载

  1. 把工作目录切到 ROUTER，运行 claude plugin uninstall agentd-router@kid551-agentd --scope project。
  2. 运行 claude plugin marketplace remove kid551-agentd。
  3. 运行 curl.exe -s -X POST http://127.0.0.1:7707/shutdown。守护进程本来没在跑的话，这条会报错，忽略即可。
  4. 删除 ROUTER 和 MARKET 两个目录。
  5. 如果设置过环境变量，运行 reg delete HKCU\Environment /v AGENTD_CLAUDE /f 删掉它。
  6. 问用户 要不要删除 AGENTD_HOME。里面是任务记录和日志，用户确认后才删。

9. 必须告诉用户的三条规则

  1. .agentd-router 标记文件只能放在 ROUTER 这个专用空文件夹里。Router 会话会禁用 Bash、Read、Edit、Write 等工具；标记文件放进代码仓库的话，用户在那个仓库里就没法正常用 Claude Code 了。
  2. 不要把 AGENTD_ROUTER=1 设成环境变量。设了之后，每个 Claude Code 会话都会变成 Router。
  3. 同一时间只开一个 Router 窗口。全机只有一个守护进程，两个 Router 会收到同样的问题和交付，容易重复回复 Worker。

Router 常用命令（给用户参考）

命令作用
/tickets列出所有任务（界面上叫「奏折」）
/ticket 1 · /router和 #1 的 Worker 直接对话 / 回到对 Router 说
/next跳到下一个在等你回复的任务
/r 你的话在和某个 Worker 单聊时，临时对 Router 说一句
/agentd status · start · restart查看 / 启动 / 重启守护进程

派活：直接说「在 <项目名> 里 <要做的事>」。验收：在面板里点「收」，或者说「1 收了」。
